## About

I'm an AI/ML engineer from Lords Institute of Engineering and Technology, focused on taking models out of notebooks and into systems people can actually use. My main project is a real-time face and voice swap platform: live webcam and microphone streams go over WebRTC to a GPU inference pipeline and come back transformed in the browser, with auth, subscriptions, and cloud deployment built around it.

## Featured Work

### [SwapX](https://github.com/MuqeetMujeeb/Deepfake), Real-Time Face and Voice Swap Platform

A browser-based SaaS for live face swapping and voice conversion. The user's webcam and microphone are streamed over WebRTC to a GPU inference server, and the transformed video and audio come back in real time, ready to use as a virtual camera and mic in Zoom, Meet, or Discord. Built on the open-source Deep-Live-Cam engine (one-shot `inswapper_128` swapping on ONNX Runtime with CUDA) and RVC voice conversion.

- Built the real-time media path with `aiortc`: SDP/ICE signaling in FastAPI, bidirectional audio and video tracks, audio resampled to 16 kHz mono in 2 s chunks for the RVC service, and backpressure that keeps at most one chunk in flight
- Root-caused a latency bug where lag grew the longer a session ran. Per-hop instrumentation and a 4-minute load test showed the browser sending about 30 fps into a pipeline that sustains about 20 to 22 fps, so the ingest queue aged from 0 to 12.6 s within 24 s. Fixed it by capping capture at 18 fps, below the pipeline's sustained throughput
- Benchmarked GPU concurrency across parallel inference processes. VRAM was never the limit (10 of 23 GB at 6 streams), but compute saturated at the second stream, with total throughput plateauing at about 28 to 33 fps. Session capacity is designed around that measurement
- Built the product backend: async SQLAlchemy 2.0 with Alembic migrations, bcrypt and Google OAuth login, opaque server-side sessions in httpOnly cookies, Stripe subscriptions with signature-verified and idempotent webhooks, an admin panel, and an `asyncio.Lock`-guarded session slot
- Deployed as Docker services (GPU inference and RVC voice containers, with model weights baked into the image) behind Caddy with automatic HTTPS, on AWS using RDS and S3. The Next.js frontend is on Vercel, and GitHub Actions redeploys the backend on every push
- Wrote a Windows companion app that captures the output window with `PrintWindow` and feeds it into a virtual camera through UnityCapture and `pyvirtualcam`

`Python` `FastAPI` `aiortc / WebRTC` `ONNX Runtime` `CUDA` `RVC` `SQLAlchemy` `Stripe` `Next.js` `TypeScript` `Docker` `AWS` `GitHub Actions`

### [Engine Wear and Maintenance Prediction](https://github.com/MuqeetMujeeb/mlops), End-to-End MLOps Pipeline

A production-style ML workflow that predicts vehicle engine wear (regression, a 0 to 100 score) and whether maintenance is due (binary classification), and segments vehicles with unsupervised clustering. It is tracked, registered, and served with MLflow.

- Nine-stage reproducible pipeline: synthetic data generation, EDA, cleaning, feature engineering, feature selection, training, registry, serving, and UI. The synthetic data comes from a known ground-truth formula with injected noise, missing values, duplicates, and impossible values, so you can check whether the models actually recover the true relationships
- Leakage-safe preprocessing: stateless cleaning happens upfront, and learned steps (imputation, scaling, encoding) are fit only on training data inside a single deployable `sklearn.Pipeline`
- Compared 11 regression and 11 classification models across linear, tree-based, distance-based, and ensemble families, including XGBoost. Evaluated with RMSE, MAE, and R² for regression, precision, recall, F1, and ROC-AUC for classification, and silhouette score with PCA for clustering
- Every run is logged to MLflow. The best model is promoted to the Model Registry under a `@champion` alias, served as a REST API with `mlflow models serve`, and used by a Streamlit prediction front end

`Python` `scikit-learn` `XGBoost` `MLflow` `Pandas` `Streamlit` `Conda`
